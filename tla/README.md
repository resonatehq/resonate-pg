# Conformance checking against the Resonate specification

Vendored from `resonatehq/resonate-specification`, `alts/unified/` at
`60485b1`. **That is the canonical copy.** This is a working copy so the checks
can run inside this repository; if the two drift, the specification repo wins.

## What this is

`Unified.tla` **is the specification** — one model, one configuration, no
per-implementation switches. Where the specification genuinely permits
several behaviours (a read may materialise or project; there may or may not
be a delivery stage before acquire; the environment fires its rules in any
order) the model offers all of them as nondeterminism.

So there is nothing to configure, and therefore nothing to configure wrongly.
An earlier design had a boolean per divergence and a "profile" per
implementation; it hid two real bugs, because a profile that sets
`CallbackExternalGuard = FALSE` is telling the model the defect is expected.

## Checking this implementation

```bash
# 1. record traces with this repo's own harness (.specula-output/harness/)
# 2. adapt them into the canonical shape
for t in .specula-output/traces/*.ndjson; do
  python3 tla/adapters/from_pg.py < "$t" > "tla/traces/$(basename $t)"
done
# 3. replay: a trace either replays or it does not
TLA_LIB=/path/to/jars tla/validate-traces.sh
```

A refusal names the exact call the specification cannot produce. That IS the
bug report.

Needs `tla2tools.jar` and `CommunityModules-deps.jar` (for `Json`) in
`$TLA_LIB`, default `tla/.tla-lib`.

## Scenarios that reach the known bug conditions

`tla/scenarios/` holds call lists **generated by the model** — each is the
shortest execution reaching a bug condition, taken from a mutation's
counterexample. They are short (3-6 calls). Script them in this repo's
harness, record the trace, replay it.

This is the gap worth closing here: the traces recorded so far are scripted
happy paths, so they never build the conditions the known bugs need. See
`COVERAGE.md` for exactly which bugs are currently detected and which only
have a property waiting for a trace to point it at.

## Notes for this implementation

resonate-pg is the only implementation with listeners, so its traces are the only ones that exercise the unblock path.  It records no task `pid`, no delivery stage and no worker claims.

## Files

| | |
|---|---|
| `Unified.tla` | the specification |
| `UTrace.tla` | replays a canonical trace against it |
| `adapters/from_pg.py` | this repo's harness output -> canonical shape |
| `validate-traces.sh` | replay every trace in `traces/` |
| `gen-scenarios.sh` | regenerate the scenarios from counterexamples |
| `run-mutations.sh` | check that each property still catches its defect |
| `MC.cfg` | the one model-checking configuration |

`TRACES.md`, `SCENARIOS.md`, `MUTATIONS.md` and `COVERAGE.md` are copied
from the specification repo and describe the method, its results, and its
limits.
